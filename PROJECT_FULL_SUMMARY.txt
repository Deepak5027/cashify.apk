====================================================================================================
1. PROJECT OVERVIEW & MISSION
====================================================================================================
Project Name : AI Daily Cash Management (FinanceAI)
Type         : Full-Stack Smart Personal Finance Tracker & AI Financial Assistant
Target OS    : Cross-platform Web Application (Desktop, Tablet, Mobile Responsive)

MISSION:
To provide users with an intelligent, seamless, and automated personal financial management platform 
that goes beyond manual transaction logging. The system leverages AI-powered receipt OCR scanning, 
natural language voice entry, conversational financial chatbot assistance, predictive machine learning 
budgeting, bank statement CSV importing, fraud detection alerts, and PDF report generation.

====================================================================================================
2. SUMMARY OF EVERYTHING DONE (WORK COMPLETED)
====================================================================================================
1. FULL-STACK TRANSFORMATION:
   - Transformed the initial front-end UI prototype into a fully functional, production-ready full-stack 
     application with real database persistence, RESTful API endpoints, and authentication guards.

2. DUAL-BACKEND ARCHITECTURE IMPLEMENTATION:
   - Node.js + Express + Prisma ORM Backend (server/): Built a complete REST API backed by SQLite for 
     local development and traditional server hosting.
   - Supabase Edge Functions + Hono + Deno Backend (supabase/): Built a cloud serverless API backend 
     utilizing Supabase KV Store and Supabase Auth.

3. AUTHENTICATION & SECURITY SYSTEM:
   - Implemented JWT (JSON Web Token) session authentication and Google OAuth 2.0 integration via Passport.js.
   - Created Supabase Auth integration with signup, login, session validation, and password reset flows.
   - Implemented protected client-side routes (`ProtectedRoute.tsx`) ensuring unauthenticated users are 
     redirected to login.
   - Added user data isolation logic so users only access their own transactions, budgets, and goals.
   - Integrated automatic demo data seeding upon initial user registration.

4. ARTIFICIAL INTELLIGENCE & MACHINE LEARNING INTEGRATIONS:
   - OCR Receipt Scanning: Integrated Tesseract.js to scan receipt images via web upload or camera capture, 
     extract text, and automatically parse merchant names, amounts, dates, line items, and categories.
   - Voice-to-Expense Logging: Built Web Speech API integration (`react-speech-recognition`) that listens 
     to spoken input, extracts dollar amounts, merchants, and categories, and logs transactions instantly.
   - Conversational AI Assistant: Created an interactive financial chatbot (`Chatbot.tsx`) that reads real 
     user financial data to answer questions about monthly spending, top categories, and savings tips.
   - Predictive Machine Learning: Integrated TensorFlow.js (`@tensorflow/tfjs`) for predicting upcoming 
     weekly spending patterns and forecasting budget consumption.
   - Fraud & Anomaly Detection: Built a rule engine evaluating transaction risk scores based on unusual 
     amounts, rapid transaction velocity, or high-risk categories.

5. BANK STATEMENT IMPORT & REPORT GENERATION:
   - CSV Parser: Built a bank statement importer supporting standard bank formats (Chase, Bank of America, 
     Wells Fargo, custom CSV) with line-by-line preview and validation before importing.
   - PDF Report Generator: Integrated jsPDF and html2canvas to generate downloadable monthly financial 
     summary reports complete with executive summaries, spending category percentages, and charts.

6. FINANCIAL CALCULATORS & TOOLS:
   - Comprehensive Financial Calculator page (`Calculator.tsx`) featuring SIP investment calculators, 
     loan EMI planners, compound interest estimators, emergency fund calculators, and tax estimators.

7. DEPLOYMENT & BATCH LAUNCH SCRIPTS:
   - Developed `start-all.bat` script in `localhost_deployment/frontend_dist/` that launches backend API 
     (Port 4000), frontend dev server (Port 5174), and Prisma Studio DB GUI (Port 5555) with one click.

8. UPI MESSAGE PARSER & SMS EXTRACTOR:
   - Built a regex-based Indian bank UPI payment SMS parser (`UpiImport.tsx` & `upiParser.ts`) supporting SBI, 
     HDFC, ICICI, Paytm, PhonePe, and GPay formats. Automatically extracts amount, transaction type 
     (debited/credited), merchant/payee name, UPI reference number, bank account last 4 digits, date, and 
     auto-assigns spending categories with an interactive bulk-editing preview table.

----------------------------------------------------------------------------------------------------
A. FRONTEND TECH STACK & PACKAGES (package.json)
----------------------------------------------------------------------------------------------------
1. React 18 (`react`, `react-dom`):
   - Purpose: Component-based UI framework for building interactive views and managing local state.
   - Why used: Provides high performance, declarative syntax, and seamless component updates via hooks.

2. TypeScript (`typescript`):
   - Purpose: Static type checking for JavaScript code.
   - Why used: Prevents runtime errors, enforces data model structures (Transactions, Budgets, Goals), and improves IDE autocomplete.

3. Vite (`vite`, `@vitejs/plugin-react`):
   - Purpose: Fast frontend build tool and development web server.
   - Why used: Instant hot module replacement (HMR), extremely fast bundle times, and modern ES module support.

4. React Router 7 (`react-router`):
   - Purpose: Client-side single-page application (SPA) routing.
   - Why used: Enables seamless page navigation without browser reloads and powers protected route wrappers.

5. Tailwind CSS 4 (`tailwindcss`, `@tailwindcss/vite`, `clsx`, `tailwind-merge`):
   - Purpose: Utility-first CSS styling framework.
   - Why used: Allows rapid UI styling with responsive utilities, sleek dark/light themes, and custom gradients.

6. Radix UI Primitives (`@radix-ui/react-*`):
   - Purpose: Accessible, unstyled UI primitives (Dialog, Dropdown Menu, Tabs, Select, Accordion, Popover, Switch, Slider).
   - Why used: Provides WCAG-compliant accessibility and smooth modal/dropdown functionality customized with Tailwind styling.

7. Lucide React (`lucide-react`):
   - Purpose: Iconography library.
   - Why used: Clean, modern SVG icons for navigation sidebars, transaction categories, status badges, and action buttons.

8. Recharts (`recharts`):
   - Purpose: Data visualization and charting library.
   - Why used: Renders dynamic, responsive bar charts, pie charts, line graphs, and spending trend curves.

9. Framer Motion / Motion (`motion`):
   - Purpose: Animation library for React.
   - Why used: Adds fluid micro-interactions, smooth page transitions, modal fade-ins, and animated progress bars.

10. Sonner (`sonner`):
    - Purpose: Toast notification system.
    - Why used: Displays non-intrusive alert toasts for successful transaction additions, updates, deletions, and error handling.

11. Tesseract.js (`tesseract.js`):
    - Purpose: Client-side Optical Character Recognition (OCR) engine.
    - Why used: Extracts raw text directly from uploaded receipt images within the browser without requiring external server OCR APIs.

12. React Speech Recognition (`react-speech-recognition`):
    - Purpose: Web Speech API wrapper for React.
    - Why used: Translates real-time microphone voice speech into text strings for voice-driven transaction logging.

13. TensorFlow.js (`@tensorflow/tfjs`):
    - Purpose: In-browser Machine Learning framework.
    - Why used: Runs predictive time-series models to forecast future spending patterns based on historical user data.

14. jsPDF & HTML2Canvas (`jspdf`, `html2canvas`):
    - Purpose: PDF creation and DOM element rendering to canvas.
    - Why used: Enables users to export dynamic, professionally styled monthly financial reports with charts to downloadable PDF files.

15. Canvas Confetti (`canvas-confetti`):
    - Purpose: Visual particle animation library.
    - Why used: Adds gamification by triggering celebratory confetti bursts when users reach 100% of a savings goal.

16. i18next & React-i18next (`i18next`, `react-i18next`, `i18next-browser-languagedetector`):
    - Purpose: Internationalization (i18n) framework.
    - Why used: Enables multi-language localization (English, Spanish, Hindi, French, German, etc.) and auto-detects browser language.

B. BACKEND TECH STACK & PACKAGES (server/package.json)
----------------------------------------------------------------------------------------------------
1. Node.js & Express (`express`):
   - Purpose: Backend web application server framework.
   - Why used: Provides light, fast REST API routing, request parsing, and HTTP endpoint handling.

2. Prisma ORM (`@prisma/client`, `prisma`):
   - Purpose: Next-generation Object-Relational Mapping (ORM) for SQL databases.
   - Why used: Provides type-safe database queries, schema migration tools (`prisma migrate`), auto-generated client code, and Prisma Studio database GUI (`npx prisma studio`).

3. SQLite (`prisma/dev.db`):
   - Purpose: Embedded lightweight SQL database engine.
   - Why used: Zero-configuration local database storing user accounts, transactions, budgets, goals, bills, and activity logs.

4. Passport.js & Google OAuth (`passport`, `passport-google-oauth20`):
   - Purpose: Authentication middleware for Node.js.
   - Why used: Secures sign-in flows with Google Social Login OAuth credentials.

5. Bcrypt (`bcrypt`):
   - Purpose: Password hashing library.
   - Why used: Hashes and salts user passwords securely before database persistence.

6. JSON Web Token (`jsonwebtoken`):
   - Purpose: Standard for compact, secure transmission of identity claims.
   - Why used: Generates and verifies bearer tokens attached to API request authorization headers.

7. Cors & Cookie-Parser (`cors`, `cookie-parser`):
   - Purpose: Middleware for handling Cross-Origin Resource Sharing and HTTP cookies.
   - Why used: Allows frontend on port 5174/5173 to communicate securely with backend API on port 4000.

8. Vitest & Supertest (`vitest`, `supertest`):
   - Purpose: Automated test runner and HTTP assertion library.
   - Why used: Executes backend unit and integration tests for API routes (`authRoutes.js`, `apiRoutes.js`).

5. DATABASE SCHEMA & DATA ARCHITECTURE (PRISMA / SQLITE / SUPABASE)
====================================================================================================
Database Engine: SQLite (Local Prisma `dev.db`) & Supabase KV Store (Cloud)

PRISMA SCHEMA MODELS (`server/prisma/schema.prisma`):

1. User Model:
   - `id` (String CUID, Primary Key)
   - `name`, `email` (Unique), `image`, `phone`, `location`, `currency`, `timezone`
   - `createdAt`, `updatedAt`, `lastLogin`, `lastLoginDevice`
   - Relations: Has many Accounts, Sessions, Transactions, Budgets, Goals, Bills, Investments, Receipts.

2. Transaction Model:
   - `id` (Int, Auto-increment)
   - `userId` (String, Foreign Key)
   - `amount` (Float), `description` (String), `category` (String), `type` ('expense' | 'income')
   - `paymentMode` ('Cash' | 'Card' | 'UPI' | 'Bank Transfer'), `date` (DateTime)
   - `riskScore` (Float), `riskReason` (String)
   - `isRecurring` (Boolean), `recurringPeriod` (String), `nextRecurringDate` (DateTime)

3. Budget Model:
   - `id` (Int), `userId` (String), `name` (String), `limit` (Float), `period` (String)

4. Goal Model:
   - `id` (Int), `userId` (String), `name` (String), `target` (Float), `saved` (Float), `dueDate` (DateTime)

5. Investment Model:
   - `id` (Int), `userId` (String), `name` (String), `amount` (Float), `createdAt` (DateTime)

6. Bill Model:
   - `id` (Int), `userId` (String), `name` (String), `amount` (Float), `dueDate` (DateTime), `paid` (Boolean)

7. Receipt & ReceiptItem Models:
   - `id` (Int), `userId` (String), `total` (Float), `merchant` (String), `date` (DateTime)
   - `items`: Relation to ReceiptItem (`name`, `price`, `quantity`)

8. Activity Model:
   - `id` (Int), `userId` (String), `action` (String), `title` (String), `details` (String), `type` (String)

9. KvStore Model:
   - Key-Value persistence table for dynamic configurations.

7. DEPLOYMENT & HOW TO RUN THE PROJECT
====================================================================================================

METHOD 1: ONE-CLICK LAUNCHER (WINDOWS BATCH SCRIPT - RECOMMENDED)
   Double-click or run:
   `localhost_deployment/frontend_dist/start-all.bat`
   
   This automatically launches three services concurrently:
   1. Express Backend Server  : http://localhost:4000
   2. Frontend Dev Server     : http://localhost:5174
   3. Prisma Studio DB GUI    : http://localhost:5555

METHOD 2: MANUAL TERMINAL COMMANDS

1. Start the Backend Server (Express + Prisma SQLite):
   ```bash
   cd server
   npm install
   npm run dev
   ```
   Backend will run on http://localhost:4000

2. Start the Frontend Development Server (Vite + React):
   ```bash
   # IMPORTANT: Run inside the project directory (Aidailycashmanagement-main):
   cd Aidailycashmanagement-main
   npm install
   npm run dev
   ```
   Frontend will run on http://localhost:5174 (or http://localhost:5173)

3. Launch Database Management GUI (Prisma Studio):
   ```bash
   cd server
   npx prisma studio
   ```
   Database GUI will open at http://localhost:5555
